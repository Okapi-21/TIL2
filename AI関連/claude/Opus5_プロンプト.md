## Opus5_プロンプト

------

Opusモデルに関しては、以下のようなプロンプトが有効

#### できるだけ返答内容は簡潔に

```bash
応答は焦点を絞り、手短かつ簡潔に。免責事項や注意書きは短くし、
応答の大部分を本題の回答に使うこと。何かの説明を求められたときは、
詳細な説明が明示的に要求されない限り、高レベルの要約を返すこと。
```



#### 明示的な検証は行わせない

「検証して」「再確認して」という指示は、多くの現場プロンプトが品質保証のために慣習的に足してきたものである。
Opus 5 は 明示的に指示されなくとも、勝手に検証を行う為、これらの指示は過剰検証によるトークンの無駄になってしまう。
公式からも 削除しても品質は落ちない、と明言されている。



#### サブエージェントは放っておくと使いすぎる

委任の効果があるのは大きくて独立した作業であり、
小さいタスクに使用するとコストと時間が無駄になる可能性がある。

```bash
サブエージェントへの委任は、広範囲にわたる複数ファイルの調査のような、
本当に独立していて並列化できる大きなタスクに限ること。
数回のツール呼び出しで自分で終えられる作業は委任しないこと。
また、自分の作業の検証やダブルチェックのためにサブエージェントを使わないこと。
1つのサブエージェントでタスクを完了できるなら複数ではなく1つを使い、
生成数は少なく保つこと。
```
