## DevOps

------

### DevOps の 4つの原則

#### 自動化

　DevOps において、最も重要な原則の一つが「自動化」である。
テスト, ビルド, デプロイ と言った繰り返し行われる作業を手動ではなく、自動で実行するようにする。
自動化することで、これらのミスを排除し、常に同じ手順で確実に作業を実行できるようになる。
また、リリースの速度の面でも一つ一つの作業を人間の手で行うよりは、自動化した方が速い。

#### 継続的な改善

　DevOpsでは、プロセスを一度作って終わりにするだけでなく、常に改善し続けることを重視する。
「どこにボトルネックがあるのか」「どの工程で時間がかかっているのか」「どの障害が繰り返し発生しているか」を定期的に振り返り、改善を行う必要がある。

#### コラボレーション

　開発チームと運用チームだけでなく、QA、セキュリティ、ビジネスなど、ソフトウェアに関わるすべてのメンバーが協力し合う文化を作ることが重要。情報を共有し、共通の目標に向かって協力することで、問題の早期発見や迅速な意思決定が可能となる。

#### フィードバックループの短縮

　コードの変更がユーザーに届くまでの時間をできるだけ短くし、その結果を素早くフィードバックとして受け取れる仕組みを作る。
フィードバックの速さがソフトウェアの品質とチームの生産性を大きく向上させる。

### lac（ Infrastructure as Code）

　IaC（ Infrastructure as Code ）とはサーバーやネットワークなどのインフラ構成を手動の操作ではなく、コードとして定義・管理する考え方のこと。

　従来のインフラ管理では、サーバーの設定を管理者が手動で行なっていたのだけれど、この方法では「いつ、誰が、何を変更したのか」が追跡しにくく、同じ構成を再現することが困難だった。サーバーの構成が10台, 100台と増えるにつれて、手動管理の限界が顕著になってくる。

　IaCでインフラ構築をコードとして管理することで、再現性、透明性が確保されるため、自動化が可能となる
