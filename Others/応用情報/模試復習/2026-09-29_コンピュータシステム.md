## 計算公式集

### 1. プリエンプティブスケジューリングの判定

```
タスクAの割り込み回数 = ceil(タスクBの周期 ÷ タスクAの周期)

タスクBが使える時間 = タスクBの周期 − (タスクAの実行時間 × 割り込み回数)

判定: タスクBが使える時間 ≥ タスクBの最大実行時間 → 完了可能
```

**CPU利用率による判定（Rate Monotonic）:**
```
U = Σ (各タスクの実行時間 ÷ 各タスクの周期)
U ≤ 1 なら理論上スケジュール可能
```


```
実効アクセス時間 = h × Tc + (1 - h) × Tm

h  : ヒット率
Tc : キャッシュメモリのアクセス時間
Tm : 主記憶のアクセス時間
```

ヒット率を求める変形:
```
h = (Tm - Te) / (Tm - Tc)

Te : 実効アクセス時間
```

### 3. HPC性能計算

```
総コア数 = ノードあたりのコア数 × ノード数
総理論ピーク演算性能 = 1コアの理論ピーク演算性能 × 総コア数
```

単位換算:
```
1 TFLOPS = 1,000 GFLOPS = 10^12 FLOPS
```

### 4. デッドロック判定

```
デッドロック発生の必要条件（4つ全て成立時に発生しうる）:
  1. 相互排除: 資源は同時に1プロセスしか使えない
  2. 保持と待ち: 資源を保持したまま他の資源を待つ
  3. 横取り不可: 他プロセスから資源を強制的に奪えない
  4. 循環待ち: プロセス間で資源の待ちが環状になる

簡易判定: 2つのプロセスの資源取得順序が逆方向の部分を持つ → 循環待ちの可能性あり
         同じ順序で取得する → 循環待ちは発生しない
```

## 問題1: プリエンプティブスケジューリング（令和5年度秋期 問17）

### 問題

プリエンプティブな優先度ベースのスケジューリングで実行する二つの周期タスクA及びBがある。タスクBが周期内に処理を完了できるタスクA及びBの最大実行時間及び周期の組合せはどれか。ここで，タスクAの方がタスクBより優先度が高く，かつ，タスクAとBの共有資源はなく，タスク切替え時間は考慮しないものとする。また，時間及び周期の単位はミリ秒とする。

| 選択肢 | タスクA 最大実行時間 | タスクA 周期 | タスクB 最大実行時間 | タスクB 周期 |
|:---:|:---:|:---:|:---:|:---:|
| ア | 2 | 4 | 3 | 8 |
| イ | 3 | 6 | 4 | 9 |
| ウ | 3 | 5 | 5 | 13 |
| エ | 4 | 6 | 5 | 15 |

- 自分の解答: **エ**
- 正解: **ア**

### 解説

#### そもそも「プリエンプティブ」とは？

「プリエンプティブ（preemptive）」とは「横取り」のこと。優先度の高いタスクAが実行可能になると、実行中のタスクBを**中断して**タスクAが先に実行される仕組み。

#### 解き方の手順

タスクBが周期内に処理を完了できるかを判定するには、**タスクBの周期内でタスクAに横取りされる時間を考慮して、タスクBの処理が終わるか**を確認する。

**選択肢アの検証:**
- タスクBの周期は8ms。この8msの間にタスクAは周期4msなので**2回**起動する
- タスクAの実行時間は1回あたり2ms × 2回 = 4ms
- タスクBが使える時間 = 8 - 4 = **4ms**
- タスクBの最大実行時間は3ms → 4ms ≥ 3ms なので**完了できる** → 正解

**選択肢エの検証（自分が選んだ答え）:**
- タスクBの周期は15ms。この15msの間にタスクAは周期6msなので **ceil(15/6) = 3回**起動する
- タスクAの実行時間は1回あたり4ms × 3回 = 12ms
- タスクBが使える時間 = 15 - 12 = **3ms**
- タスクBの最大実行時間は5ms → 3ms < 5ms なので**完了できない**

#### ポイント

- 「タスクBの周期÷タスクAの周期」の**切り上げ**で、タスクAの割り込み回数を求める
- タスクBが使える時間 = タスクBの周期 − (タスクAの実行時間 × 割り込み回数)
- CPU利用率の公式: 各タスクの（実行時間÷周期）の合計が1以下であれば、スケジュール可能

## 問題3: サーバプロビジョニングツール（令和5年度春期 問50）

### 問題

サーバプロビジョニングツールを使用する目的として，適切なものはどれか。

- ア: サーバ上のサービスが動作しているかどうかを，他のシステムからリモートで監視する。
- イ: サーバにインストールされているソフトウェアを一元的に管理する。
- ウ: サーバを監視して，システムやアプリケーションのパフォーマンスを管理する。
- エ: システム構成をあらかじめ記述しておくことによって，サーバを自動的に構成する。

- 自分の解答: **ウ**
- 正解: **エ**

### 解説

#### 「プロビジョニング」とは？

プロビジョニング（provisioning）とは「事前に準備・設定する」という意味。ITの文脈では、**サーバやネットワーク機器を使える状態にセットアップすること**を指す。

#### 各選択肢の整理

| 選択肢 | 内容 | 該当するツールの例 |
|:---:|---|---|
| ア | リモート監視 | Nagios, Zabbix（**監視ツール**） |
| イ | ソフトウェアの一元管理 | WSUS, Jamf（**ソフトウェア配布ツール**） |
| ウ | パフォーマンス管理 | Datadog, New Relic（**APMツール**） |
| エ | 構成を記述して自動構成 | Ansible, Chef, Puppet, Terraform（**プロビジョニングツール**） |

#### ポイント

- プロビジョニングツールの核心は **Infrastructure as Code（IaC）** の考え方
- サーバの構成（OS設定、ミドルウェア導入、ネットワーク設定など）を**コードとして記述**し、そのコードを実行することで**自動的に同じ環境を再現**できる
- ウ（パフォーマンス管理）との違い: 監視は「動いているものを見る」、プロビジョニングは「動く状態を作る」

## 問題4: デッドロック（令和6年度春期 問17）

### 問題

三つの資源X〜Zを占有して処理を行う四つのプロセスA〜Dがある。各プロセスは処理の進行に伴い，表中の数値の順に資源を占有し，実行終了時に三つの資源を一括して解放する。プロセスAと同時にもう一つプロセスを動かした場合に，デッドロックを起こす可能性があるプロセスはどれか。

| プロセス | 資源Xの占有順序 | 資源Yの占有順序 | 資源Zの占有順序 |
|:---:|:---:|:---:|:---:|
| A | 1 | 2 | 3 |
| B | 1 | 2 | 3 |
| C | 2 | 3 | 1 |
| D | 3 | 2 | 1 |

- ア: B, C, D
- イ: C, D
- ウ: Cだけ
- エ: Dだけ

- 自分の解答: **ウ**
- 正解: **イ**

### 解説

#### そもそも「デッドロック」とは？

デッドロックとは、**2つ以上のプロセスがお互いに相手が持っている資源の解放を待ち続けて、どちらも先に進めなくなる**状態のこと。

#### 解き方の手順

まず各プロセスの資源取得順序を整理する:
- **A**: X → Y → Z（Xを1番目、Yを2番目、Zを3番目に取得）
- **B**: X → Y → Z（Aと同じ順序）
- **C**: Z → X → Y（Zを1番目、Xを2番目、Yを3番目に取得）
- **D**: Z → Y → X（Zを1番目、Yを2番目、Xを3番目に取得）

#### AとBの場合 → デッドロックなし

AもBも **X → Y → Z** の順に取得する。同じ順序で資源を要求するプロセス同士は、先に資源を取得した方が処理を完了してから、もう一方が取得できる。**循環待ち（circular wait）が発生しない**ためデッドロックは起きない。

#### AとCの場合 → デッドロックの可能性あり

1. AがXを取得、CがZを取得（同時に1番目の資源を取る）
2. AがYを取得しようとする → 取得できる
3. AがZを取得しようとする → **Cが持っているので待ち**
4. CがXを取得しようとする → **Aが持っているので待ち**
5. A → Zを待つ → Cが持つ / C → Xを待つ → Aが持つ → **循環待ち = デッドロック！**

#### AとDの場合 → デッドロックの可能性あり

1. AがXを取得、DがZを取得（同時に1番目の資源を取る）
2. AがYを取得しようとする / DがYを取得しようとする → **どちらか一方が取得**
3. もしAがYを取得した場合:
   - AがZを待つ（Dが持っている）
   - DがYを待つ（Aが持っている）→ **デッドロック！**
4. もしDがYを取得した場合:
   - DがXを待つ（Aが持っている）
   - AがYを待つ（Dが持っている）→ **デッドロック！**

#### ポイント

- デッドロックの発生条件の一つに「循環待ち」がある
- **資源を同じ順序で取得するプロセス同士ではデッドロックは起きない**（B）
- **資源の取得順序が逆になる部分があるプロセス同士ではデッドロックが起きうる**（C, D）
- デッドロック防止の基本戦略: 全プロセスで資源取得の順序を統一する

## 問題5: HPCマシンの性能計算（令和7年度秋期 問11）

### 問題

現状のHPC（High Performance Computing）マシンの構成を，次の条件で更新することにした。更新後の，ノード数と総理論ピーク演算性能はどれか。ここで，総理論ピーク演算性能は，コア数に比例するものとする。

【現状の構成】
- (1) 一つのコアの理論ピーク演算性能は10GFLOPSである。
- (2) 一つのノードのコア数は8である。
- (3) ノード数は1,000である。

【更新条件】
- (1) 一つのコアの理論ピーク演算性能を現状の2倍にする。
- (2) 一つのノードのコア数を現状の2倍にする。
- (3) 総コア数を現状の4倍にする。

| 選択肢 | ノード数 | 総理論ピーク演算性能(TFLOPS) |
|:---:|:---:|:---:|
| ア | 2,000 | 320 |
| イ | 2,000 | 640 |
| ウ | 4,000 | 320 |
| エ | 4,000 | 640 |

- 自分の解答: **エ**
- 正解: **イ**

### 解説

#### 用語の整理

- **FLOPS**: Floating-point Operations Per Second（1秒あたりの浮動小数点演算回数）
- **GFLOPS**: 10^9 FLOPS（ギガ）
- **TFLOPS**: 10^12 FLOPS（テラ）= 1,000 GFLOPS
- **コア**: CPU内の演算を実行する処理装置
- **ノード**: コアを複数搭載したコンピュータ1台の単位

#### Step 1: 現状の値を把握する

- コアの性能: 10 GFLOPS
- ノードあたりのコア数: 8
- ノード数: 1,000
- **総コア数** = 8 × 1,000 = **8,000**
- **総理論ピーク演算性能** = 10 GFLOPS × 8,000 = 80,000 GFLOPS = **80 TFLOPS**

#### Step 2: 更新後の値を計算する

- コアの性能: 10 × 2 = **20 GFLOPS**
- ノードあたりのコア数: 8 × 2 = **16**
- 総コア数: 8,000 × 4 = **32,000**
- **ノード数** = 総コア数 ÷ ノードあたりのコア数 = 32,000 ÷ 16 = **2,000**
- **総理論ピーク演算性能** = 20 GFLOPS × 32,000 = 640,000 GFLOPS = **640 TFLOPS**

#### 間違えた原因

ノード数の計算がポイント。「総コア数を4倍」「ノードあたりのコア数を2倍」なので、ノード数は 4÷2 = **2倍**（4倍ではない）。「4倍」という数字に引きずられて4,000ノードと計算しないよう注意。

## 問題6: キャッシュメモリのヒット率（令和6年度春期 問10）

### 問題

主記憶のアクセス時間が60ナノ秒，キャッシュメモリのアクセス時間が10ナノ秒であるシステムがある。キャッシュメモリを介して主記憶にアクセスする場合の実効アクセス時間が15ナノ秒であるとき，キャッシュメモリのヒット率は幾らか。

- ア: 0.1
- イ: 0.17
- ウ: 0.83
- エ: 0.9

- 自分の解答: **イ**
- 正解: **エ**

### 解説

#### 「キャッシュメモリ」とは？

キャッシュメモリは、CPUと主記憶（メインメモリ）の間に置かれる**高速だが小容量のメモリ**。CPUが必要なデータがキャッシュにあれば高速にアクセスでき（ヒット）、なければ遅い主記憶まで取りに行く（ミス）。

#### 実効アクセス時間の公式

```
実効アクセス時間 = ヒット率 × キャッシュアクセス時間 + (1 - ヒット率) × 主記憶アクセス時間
```

この公式は「確率の加重平均」と考えるとわかりやすい:
- ヒット率 h の確率でキャッシュ（10ns）にアクセス
- (1-h) の確率で主記憶（60ns）にアクセス

#### 計算

ヒット率を h とおく:

```
15 = h × 10 + (1 - h) × 60
15 = 10h + 60 - 60h
15 = -50h + 60
50h = 45
h = 45/50 = 0.9
```

**ヒット率 = 0.9（90%）**

#### 検算

0.9 × 10 + 0.1 × 60 = 9 + 6 = 15（ナノ秒）→ 一致

#### ポイント

- 実効アクセス時間が15nsと、キャッシュの10nsに非常に近い → ヒット率は高いはず → 0.9は直感的にも妥当
- この公式は応用情報の頻出パターン。必ず覚える

## 問題8: シミュレーションの特徴（令和6年度春期 問15）

### 問題

コンピュータの性能評価には，シミュレーションを用いた方法，解析的な方法などがある。シミュレーションを用いた方法の特徴はどれか。

- ア: 解析的な方法よりも計算量が少なく，効率的に解が求まる。
- イ: 解析的な方法よりも，乱数を用いることで高精度の解が得られる。
- ウ: 解析的に解が求められないモデルに対しても，数値的に解が求まる。
- エ: 解析的に解が求められるモデルの検証には使用できない。

- 自分の解答: **ア**
- 正解: **ウ**

### 解説

#### 「解析的な方法」と「シミュレーション」の違い

| | 解析的な方法 | シミュレーション |
|---|---|---|
| やり方 | 数学的な公式や理論で**厳密に**解を求める | コンピュータ上でモデルを模擬実行して**近似的に**解を求める |
| 精度 | 理論上は厳密解が得られる | 試行回数を増やせば近似精度は上がるが厳密解ではない |
| 計算量 | モデルが単純なら少ない | 一般に解析的方法より**計算量は多い** |
| 適用範囲 | 数式で表現できるモデルに限られる | **複雑なモデルにも適用できる** |

#### 各選択肢の判定

- **ア ×**: シミュレーションは解析的方法より計算量が**多い**のが一般的。効率的とは言えない
- **イ ×**: 乱数を使うモンテカルロ法などは便利だが、解析的方法より「高精度」とは言えない。乱数による誤差が含まれる
- **ウ ○**: これがシミュレーションの最大のメリット。解析的に解けない複雑なモデル（待ち行列の複雑な組み合わせなど）でも、数値的に近似解を得ることができる
- **エ ×**: 解析的に解が求められるモデルの検証にも使用**できる**。むしろ解析解との比較でシミュレーションモデルの妥当性を検証することは一般的

#### ポイント

- シミュレーションの最大の長所 = **解析的に解けない問題にも対応できる汎用性**
- 短所は計算量の多さと近似解である点
- 待ち行列理論の問題などで「解析的に解けないからシミュレーションする」という文脈でよく出題される
