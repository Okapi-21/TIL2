## Linux（syslog, rsyslog）

syslog と rsyslog は linux システムでログメッセージを管理、収集、処理するためのユーティリティ（コンピューターやOSの動作を補助・支援するためのソフトウェアツールのこと）である。

#### syslog

　syslogは、UNIX系システムで最も一般的に使用されるログメッセージ処理システムの標準的な実装であり、システムやアプリケーションからのログメッセージを処理し、適切なログファイルに書き込む役割を担っている。

　主な機能としては、以下のようなものがある。

1. ログメッセージの収集と処理

   設定ファイル： `/etc/rsyslog.conf` or `/etc/rsyslog.d/*.conf`

    どのファシリティ（ログの発生源）のどのレベルのログをどこに書き込むのかをルールとして定義する

   ```bash
   httpd.info		/var/log/httpd.log　　#httpdのinfoレベル以上を記録する
   ```

   

2. ログレベルに基づくフィルタリング
   設定ファイル：`/etc/rsyslog.conf`

   ログには重要度に応じた「ログレベル」が存在しており、代表的なものは以下のようになっている。

   > ミドルウェアでは最初から「ログレベル」が設定されているので、使用者は syslog でどのレベルのログを収集するのかを設定するだけでOK

   | レベル  | 内容                         |
   | ------- | ---------------------------- |
   | emerg   | システムが使用不能な緊急状態 |
   | alert   | 即時対応が必要               |
   | crit    | 重大なエラー                 |
   | err     | 一般的なエラー               |
   | warning | 警告                         |
   | notice  | 通常だが注意が必要           |
   | info    | 一般的な情報                 |
   | debug   | デバッグ情報                 |

   

3. ログのローテーション
   設定ファイル：`/etc/logrotate.conf` または `/etc/logrotate.d` 配下ファイル
   ログローテーションは syslog自体というよりも、 lorgotate というツールが担当する。
   古いログを圧縮・削除することでディスクの圧迫を防ぐことができる。

   基本的な設定項目は以下の通りである。

   ```bash
   /var/log/messages {
       weekly          # 週次でローテーション
       rotate 4        # 4世代分保持
       compress        # 古いログをgzip圧縮
       missingok       # ファイルがなくてもエラーにしない
       notifempty      # ファイルが空ならローテーションしない
   }
   ```

   

4. リモートログ収集
    他のシステムからログを受信（サーバ側）したり、自システムのログを他サーバへ送信（クライアント側）したりする設定のこと

   ```bash 
   # ログを送信する側（クライアント）
   *.* @192.168.1.100:514    # UDPで送信
   *.* @@192.168.1.100:514   # TCPで送信（rsyslogの拡張機能）
   
   # ログを受信する側（サーバ）
   $ModLoad imudp           # UDPモジュールを読み込む
   $UDPServerRun 514        # UDPポート514で受信
   
   $ModLoad imtcp           # TCPモジュールを読み込む
   $InputTCPServerRun 514   # TCPポート514で受信
   ```

   

#### rsyslog 

　rsyslogは、syslogの改良版であり、機能が拡張されたログメッセージ処理システムのことである。
rsyslogはsyslogとの互換性を保ちながら、より高度な機能を提供する。

　主な改善点としては、以下のようなものが挙げられる。

1. パフォーマンスの向上
2. 柔軟なフィルタリング及びログのルーティング機能
3. TCPおよびTLSを介したセキュアなリモートログ収集
4. メッセージのキューイグと転送機能
5. ログデータのディスクキャッシュ

　1のパフォーマンスの向上に関しては、自動稼働であるが、2~5に関しては追加設定が必要になる。

 rsyslogは、syslogと互換性があり、通常はsyslogの代替として使用されるが、追加の機能やパフォーマンス向上を求める場合にも適している。

　CentOS（およびその派生ディストリビューションのRHEL）では、デフォルトで rsyslog がログの収集と管理を担当している。rsyslogはシステムの様々なイベントやプロセスから生成されるログメッセージを収集し、指定されたログファイルに書き込んだり、リモートシステムに送信したりする役割を果たしている。

　rsyslog の設定ファイルは通常、`/etc/rsyslog.conf` に存在している。
このファイルには、どのログメッセージをどのファイルに書き込むか、リモートシステムにログを送信する方法などが定義されている。また、`/etc/rsyslog.d/` ディレクトリには、さらに詳細な設定が含まれる場合がある。

#### ① 中央ログサーバへの信頼性の高い転送

複数のサーバ（クライアント）からログを1台の中央サーバに集約する、最もよく使われる構成です。
単純な転送だけでなく、転送先サーバが一時的にダウンした場合でもログを失わないよう、
**ディスクアシストキュー**を組み合わせるのが実運用での定番パターンです。

##### 構成イメージ

```
[クライアントA] ─┐
[クライアントB] ─┼──→ [中央ログサーバ]
[クライアントC] ─┘
```

##### 動作の流れ

1. クライアントがログを TCP で中央サーバへ転送する
2. 中央サーバがダウンした場合、ログはクライアントの**メモリキュー**に保持される
3. メモリが不足した場合は自動的に**ディスクキャッシュ**に退避される
4. 中央サーバが復旧すると、蓄積されたログが自動的に送信再開される

##### 設定例（クライアント側 `/etc/rsyslog.conf`）

```conf
# ローカルソケットからのメッセージを受信するモジュール
module(load="imuxsock")

# キューファイルの保存先ディレクトリ
global(workDirectory="/rsyslog/work")

action(
  type="omfwd"
  target="loghost.example.net"   # 転送先の中央サーバのホスト名またはIP
  port="10514"                   # 転送先のポート番号
  protocol="tcp"                 # UDPではなくTCPを使用（信頼性のため）
  action.resumeRetryCount="-1"   # -1 = 無限リトライ（サーバ復旧まで諦めない）
  queue.type="LinkedList"        # 非同期処理用のメモリキュー
  queue.filename="srvrfwd"       # ファイル名を指定することでディスクアシスト化
  queue.saveOnShutdown="on"      # rsyslog停止時にキュー内データをディスクへ保存
)
```

##### ポイント解説

| パラメータ                     | 役割                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| `protocol="tcp"`               | UDP と違い、到達確認ができるため信頼性が高い                 |
| `action.resumeRetryCount="-1"` | サーバが復旧するまで無限にリトライする                       |
| `queue.type="LinkedList"`      | メッセージをメモリ上にキューイングし、非同期で転送する       |
| `queue.filename="srvrfwd"`     | ファイル名を指定することで、メモリ溢れ時にディスクへ自動退避（DA化） |
| `queue.saveOnShutdown="on"`    | rsyslog の正常終了時にメモリ上のキューをディスクに保存し、再起動後も引き継ぐ |

##### 複数サーバへの転送

転送先が複数ある場合は、アクションを並べるだけで対応できます。
ただし、`queue.filename` は各アクションで**必ず異なる名前**を指定する必要があります。

```conf
# 転送先1（東日本リージョン）
action(
  type="omfwd"
  target="east-loghost.example.net"
  protocol="tcp"
  action.resumeRetryCount="-1"
  queue.type="LinkedList"
  queue.filename="srvrfwd1"      # ← 一意の名前
  queue.saveOnShutdown="on"
)

# 転送先2（西日本リージョン）
action(
  type="omfwd"
  target="west-loghost.example.net"
  protocol="tcp"
  action.resumeRetryCount="-1"
  queue.type="LinkedList"
  queue.filename="srvrfwd2"      # ← 一意の名前
  queue.saveOnShutdown="on"
)
```

2つのキューは独立して動作するため、一方の転送先がダウンしても
もう一方へのリアルタイム転送は影響を受けません。

#### ② フェイルオーバー（ログサーバ冗長化）

##### 概要

プライマリサーバがダウンした際に、自動でセカンダリサーバへ切り替える構成です。
**① の「並列転送」とは異なり**、通常時は1台のサーバにのみ送り、
障害発生時にのみ次のサーバへ切り替える「優先順位付き転送」です。

##### 構成イメージ

```
                          ┌→ [プライマリサーバ]         ← 通常時はここ
[クライアント] ──────────┼→ [セカンダリサーバ1]        ← プライマリ障害時
                          ├→ [セカンダリサーバ2]        ← セカンダリ1も障害時
                          └→ [ローカルバッファファイル]  ← 全滅時の最終手段
```

##### 動作の流れ

1. 通常時はプライマリサーバへのみ転送する
2. プライマリが応答しなくなると、自動でセカンダリサーバ1に切り替わる
3. セカンダリ1も応答しない場合は、セカンダリサーバ2に切り替わる
4. すべてのサーバが落ちている場合は、ローカルファイルに一時保存する
5. いずれかのサーバが復旧すると、自動的に優先度の高いサーバへ戻る

##### 設定例（`/etc/rsyslog.conf`）

```conf
# フェイルオーバー用のルールセットを定義（キュー付きで非同期処理）
ruleset(name="forwarding" queue.type="linkedList" queue.filename="fwdq") {

  # 【優先度1】プライマリサーバ（通常時はここにのみ送られる）
  action(
    type="omfwd"
    target="primary-syslog.example.com"
    port="10514"
    protocol="tcp"
  )

  # 【優先度2】セカンダリサーバ1（プライマリが停止した時のみ実行）
  action(
    type="omfwd"
    target="secondary-1-syslog.example.com"
    port="10514"
    action.execOnlyWhenPreviousIsSuspended="on"  # ← 前のアクションが失敗した時のみ
  )

  # 【優先度3】セカンダリサーバ2（プライマリ＆セカンダリ1が停止した時のみ実行）
  action(
    type="omfwd"
    target="secondary-2-syslog.example.com"
    port="10514"
    action.execOnlyWhenPreviousIsSuspended="on"
  )

  # 【最終手段】全サーバ停止時はローカルファイルに保存
  action(
    type="omfile"
    tag="failover"
    file="/var/log/localbuffer"
    action.execOnlyWhenPreviousIsSuspended="on"
  )
}

# "error" を含むメッセージをフェイルオーバールールセットで処理
if($msg contains "error") then {
  call forwarding
}
```

##### ポイント解説

| パラメータ                                    | 役割                                                         |
| --------------------------------------------- | ------------------------------------------------------------ |
| `action.execOnlyWhenPreviousIsSuspended="on"` | 直前のアクションが失敗・停止している場合のみ実行する（フェイルオーバーの核心） |
| `ruleset(...) { }`                            | 複数アクションをひとまとめにし、ルールセット単位でキューを持たせる |
| `queue.type="linkedList"`                     | ルールセット全体を非同期処理しつつ、内部アクションは同期で動かし障害検知を可能にする |
| `file="/var/log/localbuffer"`                 | 全サーバ障害時の最終バッファ。復旧後に手動またはスクリプトで再送できる |

> **注意：** アクション個別にキューを設定するとフェイルオーバーが機能しません。
> キューは必ず `ruleset` 側に設定してください。
> アクション個別のキューは非同期処理になり、障害検知ができなくなるためです。

#### まとめ

| 構成                   | 用途                     | 特徴                                         |
| ---------------------- | ------------------------ | -------------------------------------------- |
| 中央ログサーバへの転送 | 複数サーバのログ一元管理 | 並列転送・障害時のディスクバッファリング     |
| フェイルオーバー構成   | ログサーバの冗長化       | 優先順位付き切り替え・最終手段のローカル保存 |
