## 環境構築, 用語理解

### 用語理解

- AWSアカウント
  　AWSと契約する単位のこと、請求情報やリソース、各種設定の入れ物となっていて、企業や個人ごとに一つ作成する。例えば、「学習用に自分のアカウント」「会社の本番運用のアカウント」というように、目的別に複数のアカウントを使い分けることもある。
- ルートユーザー
  　AWSアカウントを作成したときのメールアドレスでログインするユーザであり、アカウント内の全ての操作ができる最上位の権限を持つ。請求情報の変更やアカウントの解約まで実行できるため、強力すぎて、日常操作には向かない。鉄則として、**ルートユーザは封印して使わない**という運用を徹底するのがベター
- IAMユーザー
  　AWSアカウントの中に作成するユーザーであり、必要な権限だけを付与できる。
  日常作業はIAMユーザーで行い、人ごと、役割ごとにIAMユーザーを作成して、権限を使い分けるのが基本的な使い方になる。

##### 課金事故防止策（AWS Budgetds）

　AWS Budgetsは月額の予算を設定し、超過しそうになるとメールで通知を行ってくれるサービスのこと、
学習中は「月＄５で警告」「月＄10で再傾向」というように保守的な予算を組んでおくと、想定外の請求を防ぐことができる。



### ローカル環境セットアップ

　AWSをコードで操作するためには、ローカルPCに次の２つのツールを揃える必要がある。

- AWS CLI：AWSをコマンドラインから操作するための公式ツール
- Terraform：インフラをコードで管理するためのツール



#### AWS CLI インストール

```bash 
# aws cli インストール
brew install awscli

# バージョン確認
aws --version
```

#### terraform インストール

```bash
# HashCorp の著名鍵の追加
brew tap hashicorp/tap

# terraformのインストール
brew install hashicorp/tap/terraform

# バージョン確認
terraform -version 
```

#### AWS CLI アクセスキーの設定

```bash
aws configure

#以下の質問に答えていく
AWS Access Key ID [None]:     ← アクセスキー ID を貼り付け
AWS Secret Access Key [None]: ← シークレットアクセスキーを貼り付け
Default region name [None]:   ← ap-northeast-1 と入力
Default output format [None]: ← json と入力
```

#### 挙動確認

```bash
aws sts get-caller-identity

#以下のようなjsonが返ってくるとOK
{
    "UserId": "xxxxxx",
    "Account": "xxxxxxx",
    "Arn": "arn:aws:iam::xxxxxxxx:xxxxxxx/xxxxxxxxxx"
}
```
