### モデル

#### モデル

　LaravelのモデルはDBへのアクセスやビジネスロジックの実装に責任を持つ部分になる。
Laravelのモデルは主に、Eloquentで実装されていて、標準で様々な機能を提供している。

#### Eloquent

　Eloquentは、LaravelのデフォルトのORM（Object-Relational Mapping）ライブラリであり、Laravelのモデル層の実装に使用される。ORMはデータベースのテーブルとオブジェクト指向プログラミングのモデルをマッピングし、DBとのやり取りを簡単にするためのツールです。

#### 命名規則

- モデルのクラス名を単数形
- テーブル名を複数形
- モデルのクラス名が複数の単語で構成されている場合
  - クラス名をキャメルケース（頭文字を大文字にする書き方）で記述
  - 対応するテーブル名はスネークケース（小文字とアンダースコアで構成する記法）で記述

#### メソッド一覧（一部）

| メソッド          | 概要・用途                                     | 例（使い方）                                                 | 備考                     |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------------ | ------------------------ |
| `new`             | 新しいオブジェクトを作成。まだDB保存されない。 | `$user = new User([...]);`                                   | 保存は `save` メソッドで |
| `save`            | オブジェクトをDBに保存（新規・更新）。         | `$user->save();`                                             |                          |
| `create`          | 新規レコードを直接DBに保存。                   | `$user = User::create([...]);`                               | バリデーションは事前に   |
| `all`             | 全レコードを取得。                             | `$users = User::all();`                                      |                          |
| `find`            | ID指定で1件取得。なければ `null`。             | `$user = User::find(1);`                                     |                          |
| `findOrFail`      | ID指定で1件取得。なければ例外をスロー。        | `$user = User::findOrFail(1);`                               |                          |
| `where`           | 条件指定で取得。                               | `$users = User::where('name', 'RUNTEQ')->get();`             | 複数件返る               |
| `update`          | 既存レコードを更新。                           | `$user->update(['name' => 'Runtekun']);`                     |                          |
| `delete`          | レコードを削除。                               | `$user->delete();`                                           |                          |
| `destroy`         | ID指定で直接削除。複数IDも可。                 | `User::destroy(1);`<br>`User::destroy([1, 2, 3]);`           |                          |
| `orderBy`         | 並び順指定で取得。                             | `$users = User::orderBy('name')->get();`<br>`orderBy('name','desc')` | 昇順/降順両方可          |
| `count`           | レコード数を取得。                             | `$total = User::count();`<br>`User::where('age', '>=', 18)->count();` | 条件付きも可             |
| `latest`/`oldest` | 作成日時で並び替え（降順/昇順）。              | `$lastUser = User::latest()->first();`                       | `created_at`基準         |
| `first`           | 取得した中で最初の1件を返す。                  | `$firstUser = User::first();`                                | 条件付きも可             |

---

> **補足**  
> - 取得結果がない場合、`first`, `find`は`null`を返します。  
> - 例外が必要な場合は`findOrFail`を使います。  
> - `create`はバリデーションを自動でしないため、事前にチェック推奨です。

### Eloquentのイベントとメソッドまとめ

#### イベントとは
Eloquentモデルで、データの保存や削除など**特定のアクションの前後に自動で呼び出される処理**です。
 データの整合性確保や、処理自動化によく使われます。
＊アクションの前後で自動的に呼び出されるので、うまく活用すれば、煩雑な処理を削減したり、自動化したりすることができる。

主なイベント種類：
- **creating**: レコード作成前
- **created**: レコード作成後
- **updating**: レコード更新前
- **updated**: レコード更新後
- **saving**: 保存前（新規作成＋更新）
- **saved**: 保存後
- **deleting**: 削除前
- **deleted**: 削除後

> イベントを使いすぎると、タイミング管理が難しくなるので注意。

---

#### 主なイベントの例

#### saving  
保存直前に処理を実行  
（例：name属性を大文字に変換）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::saving(function ($user) {
            $user->name = ucfirst($user->name);
        });
    }
}
```

---

#### creating  
新規作成直前に処理を実行  
（例：signup_date属性に現在日時を設定）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::creating(function ($user) {
            $user->signup_date = now();
        });
    }
}
```

---

#### updating  
更新直前に処理を実行  
（例：updated_at属性に現在日時を設定）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::updating(function ($user) {
            $user->updated_at = now();
        });
    }
}
```

---

### saved  
保存後に処理を実行  
（例：ログ記録）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::saved(function ($user) {
            Log::info("User {$user->id} was saved at " . now());
        });
    }
}
```

---

### created  
新規作成後に処理を実行  
（例：ウェルカムメール送信）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::created(function ($user) {
            Mail::to($user->email)->send(new WelcomeMail($user));
        });
    }
}
```

---

#### updated  
更新後に処理を実行  
（例：更新時のログ記録）

```php
class User extends Model
{
    protected static function boot()
    {
        parent::boot();

        static::updated(function ($user) {
            Log::info("User {$user->name}'s profile was updated!");
        });
    }
}
```

---

#### クラスメソッドとインスタンスメソッド

#### クラスメソッド
- クラス自体に紐づくメソッド（`static`付き）
- クラス全体で共通の処理、一括操作などに使う
- コードの可読性・再利用性アップ

#### インスタンスメソッド
- オブジェクト（インスタンス）に紐づくメソッド
- 個々のデータや状態に応じて操作
- モデル内のロジック整理・再利用に役立つ

---

### EloquentのModel、Builder、Relation、Collection

Eloquentのコードを読むときは、今扱っている値が次のどれなのかを区別することが重要である。

| 種類 | 役割 | OneSendの例 |
|---|---|---|
| Model | DBの1レコードを表すオブジェクト | `$transfer`、`$file` |
| Eloquent Builder | SQLの検索条件を組み立てる | `Transfer::query()->where(...)` |
| Relation | モデル間の関連と、その検索条件を表す | `$transfer->files()` |
| Collection | 複数のModelをまとめたコレクション | `$transfer->files` |

次のコードは、左から右へ戻り値の種類が変わる。

```php
$transfer = Transfer::query()
    ->where('token', $token)
    ->firstOrFail();
```

```text
Transfer::query()        → Eloquent Builder
where(...)               → 条件が追加されたBuilder
firstOrFail()            → 見つかったTransferモデル
```

`where()`の時点では、まだTransferレコードは取得されていない。`firstOrFail()`、`first()`、`get()`、`count()`などを呼んだ段階でSQLが実行される。

### `firstOrFail()`

```php
$transfer = Transfer::query()
    ->where('token', $token)
    ->firstOrFail();
```

条件に一致する最初のモデルを返す。見つからない場合は`ModelNotFoundException`を投げる。

通常のLaravelのHTTP処理では、この例外が404 Not Foundレスポンスへ変換される。そのため、次のような分岐を毎回書かずに済む。

```php
$transfer = Transfer::query()->where('token', $token)->first();

if ($transfer === null) {
    abort(404);
}
```

使い分けは次のとおり。

| メソッド | 見つかった場合 | 見つからない場合 |
|---|---|---|
| `first()` | Model | `null` |
| `firstOrFail()` | Model | 例外。HTTP処理では通常404 |
| `find($id)` | Model | `null` |
| `findOrFail($id)` | Model | 例外。HTTP処理では通常404 |

### リレーションの`()`あり・なし

Transferモデルには次のリレーションが定義されている。

```php
public function files(): HasMany
{
    return $this->hasMany(TransferFile::class);
}
```

呼び出し方によって意味が変わる。

```php
$transfer->files() // HasMany Relation。追加条件を指定できる
$transfer->files   // 関連するTransferFileのCollection
```

例えば、特定のファイルだけ検索する場合はRelationとして呼ぶ。

```php
$file = $transfer->files()
    ->whereKey($fileId)
    ->firstOrFail();
```

Bladeで一覧表示する場合はCollectionとして参照する。

```blade
@foreach ($transfer->files as $file)
    {{ $file->file_name }}
@endforeach
```

### `load()`と`withCount()`

```php
$transfer->load([
    'files' => fn ($query) => $query->withCount([
        'downloadLogs as download_count' => fn ($query) => $query
            ->where('action', 'download'),
    ]),
]);
```

`load()`は、すでに取得済みのModelへリレーションを追加で読み込む。これをEager Loadingという。

`withCount()`は、関連レコード数をSQLで集計して属性として追加する。この例では、各TransferFileに`download_count`が追加される。

そのためBladeでは次のように参照できる。

```blade
{{ $file->download_count }}
```

`download_count`というDBカラムが実在するわけではなく、検索結果へ追加された集計値である。

### `lockForUpdate()`とDBトランザクション

```php
$file = DB::transaction(function () use ($transfer, $fileId) {
    return $transfer->files()
        ->whereKey($fileId)
        ->lockForUpdate()
        ->firstOrFail();
});
```

`lockForUpdate()`は、取得したDB行を更新用にロックする悲観的ロックである。

OneSendでは、同じファイルへ同時にダウンロード要求が来たとき、両方が同じダウンロード回数を見て上限を超えることを防ぐ目的で使っている。

```text
リクエストA：対象行をロック → 回数確認 → 履歴保存 → commit
リクエストB：Aのロック解除を待つ → 最新回数を確認
```

ロックは処理のまとまりが分からなければすぐ解除されてしまうため、原則として`DB::transaction()`内で使用する。

`DB::transaction()`のクロージャが正常終了すればcommitされ、例外が発生すればrollbackされる。クロージャが返した値は、`DB::transaction()`の戻り値になる。

### `DownloadLog::create()`の裏側

#### 疑問：モデルに定義していない`create()`をなぜ呼べるのか

```php
DownloadLog::create([
    'transfer_id' => $transfer->id,
    'transfer_file_id' => $file->id,
    'action' => 'download',
    'ip_address' => $request->ip(),
]);
```

`DownloadLog`自身には`create()`が定義されていない。また、正確には`create()`が単純なstaticメソッドとして親Modelに定義されているわけでもない。

Laravel 13では、概ね次の順番でEloquent Builderへ処理が転送される。

```text
DownloadLog::create(...)
  ↓ Model::__callStatic()
新しいDownloadLogインスタンスへ転送
  ↓ Model::__call()
newQuery()でEloquent Builderを作る
  ↓ Eloquent Builder::create()
新しいDownloadLogを作成してsave()
```

EloquentはPHPの`__callStatic()`と`__call()`というマジックメソッドを利用し、モデルに直接定義されていない呼び出しをBuilderへ転送している。

したがって、初心者の段階では次の理解でよい。

> `ModelName::create()`、`ModelName::where()`などは、Eloquentがモデルを入口として提供している検索・保存APIである。

ただし、コードの定義元を厳密に調べる場合は、ModelだけでなくEloquent Builderへの転送も確認する。

#### `::`と`->`

```php
DownloadLog::create([...]); // クラス名を入口にEloquent APIを呼ぶ
$log->save();               // 特定のDownloadLogインスタンスを保存する
```

- `::`：クラスを入口に定数やstatic呼び出しへアクセスする記号
- `->`：特定のオブジェクトのプロパティやメソッドへアクセスする記号

`::`が付いていても、内部実装が必ず単純なstaticメソッドとは限らない。LaravelではFacadeやEloquentのマジックメソッドによる転送が使われることがある。

#### Fillable（一括代入の許可リスト）

```php
#[Fillable([
    'transfer_id',
    'transfer_file_id',
    'action',
    'ip_address',
])]
class DownloadLog extends Model
```

`Fillable`は、`create()`や`fill()`で一括代入を許可する属性の一覧である。

一覧にない属性を一括代入すると、Laravelの設定によって破棄されるか`MassAssignmentException`になる。どちらになるかへ依存せず、入力値をそのまま`create($request->all())`へ渡さないことが重要である。

> **補足**  
> `#[Fillable([...])]`はPHPのアトリビュート構文を利用したLaravel 13の書き方。従来の`protected $fillable = [...]`も、同じ一括代入許可リストを表す。

### Eloquentコードを読むチェックリスト

1. 現在の値はModel、Builder、Relation、Collectionのどれか。
2. SQLが実行されるのはどのメソッドか。
3. 見つからない場合は`null`か、例外か。
4. `()`ありのリレーションか、プロパティ形式の取得結果か。
5. 保存処理ならFillableとトランザクションを確認したか。
6. 並行処理があるならロック範囲を確認したか。
